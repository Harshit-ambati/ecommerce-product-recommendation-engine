# Synthetic shopping dataset

## Provenance

Generated locally by `recommender/data.py` using NumPy with default seed 42. No real customer data or downloaded dataset is used. The generator is the dataset-source evidence required by the assessment. No separate third-party dataset license applies; this repository does not currently grant a public open-source license.

## Schema

- Products: unique `product_id`, display `name`, `category`, `style`, `brand`, positive synthetic `price`, and `available_at`.
- Interactions: unique `event_id`, simulated `user_id`, valid `product_id`, `event_type` (view/cart/purchase), and `timestamp`.

There are 360 products in six categories and 300 shoppers. Simulation runs January 1 through June 29, 2025, using one consistent synthetic time basis. New users join on days 120 and 150; new product cohorts launch on days 100, 120 and 150. Product metadata is fixed and known at launch; stock depletion is not simulated. Prices use arbitrary synthetic currency units.

## Generation assumptions

Latent category preferences, preferred style, budget and activity differ across shoppers. Product appeal is uneven. Sampling combines preference, style, price fit, popularity and mild seasonality. Events are stochastic and repeat visits are retained. Latent variables are never exported as model features.

This supplies learnable structure but does not reproduce real exposure bias, conversion funnels, returns, households, marketing campaigns or stock changes. Results are not unbiased estimates of production quality. A licensed real-data evaluation is a future extension.

## Quality handling

Validation rejects missing required values, duplicate IDs, nonpositive/nonfinite prices, unknown events, invalid product references and events before launch. The generated dataset has no missing cells or duplicate event IDs. Repeated shopper-product interactions are valid separate events. Logarithmic event weighting limits repeat-activity domination. Bounded synthetic prices need no clipping; external data would need an explicit missing-value/outlier policy.

The manifest records seed, cutoffs, package versions and data SHA-256 hashes. Generated data is ignored by Git and regenerated by the training command.
